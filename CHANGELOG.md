# Changelog

## 3.0.0, 2026-10-05

Built on [Slipway](https://github.com/thenavidm/slipway) 0.1.20. The 12 tools keep their names and arguments, and every difference below was measured against 2.0.1, the last version on npm, before release.

- **A person approves each confirmed operation over MCP.** All 6 still need confirmation. Claude Code (2.1.246 and later) shows its own prompt, and a client that can show forms asks with an approval form whose one box starts unticked. Approvals are signed, bound to the exact call and work once. Where a client can do neither, the model's `confirm: true` still counts, and `SENJA_CONFIRM=model` makes it enough everywhere. The refusal and the approval form both say what 2.0 said, that the call may import or publish testimonials, change tags, permanently delete proof, send invite/follow-up emails or save private testimonial files, and the audit log records who approved each one.
- **`SENJA_ALLOW_DESTRUCTIVE=0` still refuses all 6**, confirmed or not, and `SENJA_READ_ONLY=1` still leaves only the 6 reads.
- **Senja's status picks the exit code.** A request Senja rejects (400 or 422) exits 2 instead of 5, and a removed resource (410) 3 instead of 5. 401 and 403 still exit 4, 404 3, 429 7, a server error 5, and an unknown profile or nothing configured 10. 1 now means an unexpected error.
- **`which <words>` finds a command**, and `agent-context` describes every command, flag and setting as JSON. In Codex 0.159.3, finding the command that sends testimonial invites and its flags took a median of 126,370 input tokens over the CLI instead of 125,564 (five runs each). Every 2.0.1 run took five or six commands, a failed guess at `schema` or at the command's name, then the command list, the command's help and its schema. Two 3.0.0 runs asked `which sends testimonial invites`, whose answer carries the command's help, and read the schema next: three commands, 83,464 and 83,451 tokens. The other three asked `which testimonial invites`, which fits the invite command and the two reviewed-batch commands alike, so it lists them, then read the command list, the help and the schema: five commands, as 2.0.1 took, and 806 tokens more, for 3.0.0's longer general help. Over all five runs 3.0.0 averaged 109,209 tokens and 2.0.1 134,461.
- **`install <client>`** adds the server to Claude Code, Codex, Claude Desktop, Cursor, VS Code or Gemini CLI in each one's own format, and **`senja-mcp --http`** serves the same tools over Streamable HTTP, on 127.0.0.1:8787 unless told otherwise.
- **A smaller tool list.** The testimonial integrations and media are written once and referred to, so the list is 5,510 o200k tokens instead of 5,696. With every tool loaded, Claude Code 2.1.286 spends 7,551 tokens a message on the list instead of 7,900.
- **Less work to start.** Each input and body schema now compiles on its first use rather than at load, and the entry turns on Node's compile cache. The server spends 194 ms of CPU before its first answer where 2.0.1 spent 241, and answers in 153 ms of wall time instead of 164 (median of 21 runs, taking turns on one Mac). npx installs 10 dependencies instead of 94. A test still compiles every schema.
- **`doctor --network` reads one testimonial**, as 2.0's did.
- **Docs.** README section 7 has the measured Claude Code and Codex costs, where 2.0 said they were pending, and the exit codes say what 2 covers.

### Upgrading

Over MCP, expect an approval prompt or form before any confirmed operation; a headless agent that should run them with `confirm: true` alone needs `SENJA_CONFIRM=model`. A script that read exit 5 as a rejected request should read 2, and as a removed resource 3. An error is now one JSON object with `error`, Slipway's `code` (`usage`, `refused`, `auth`, `not_found`, `rate_limited`, `api`, `not_configured`) and a `hint`, plus Senja's `status` when it answered; 2.0.1 printed the tool's JSON inside the `error` string. Over MCP, an argument that fails the schema comes back as the MCP SDK's own message, "Input validation error: …", instead of JSON. With `SENJA_READ_ONLY=1`, a client that calls a hidden tool gets "tool not found" instead of a refusal naming `SENJA_READ_ONLY`, and that call is not in the audit log; the CLI still names the setting. The audit log's lines gain `confirmed_by`, and each allowed call is followed by a `done` or `failed` line. A script that pipes JSON-RPC into the server must keep stdin open until it reads the answer: the server now stops when its input ends, as the MCP stdio binding asks. `--http` refuses a page from another site unless `SENJA_HTTP_ALLOWED_ORIGINS` lists it. Some terminal screens grew: the general help by 95 tokens, for `which`, `install`, what each setting is for and the exit codes; the command list by 16; and a missing argument's error by 15, for its code and a hint. Over MCP, Codex now prints `create_testimonial` with its argument comments, 1,692 characters more, which it leaves out of a schema as large as 2.0.1's was, so a discovery task read a median of 45,393 input tokens instead of 44,983. `SKILL.md` is 82 tokens longer in Claude Code, because it says how approval works over MCP and how `which` finds a command, and that exit 1 is an unexpected error and 2 also an unknown command or a hidden write.

## 2.0.1, 2026-10-04

- **`npx -y @thenavidm/senja-mcp-cli` starts the MCP server whatever order npm keeps.** npx starts whichever binary the npm registry lists first when they share one file, and the registry does not keep the published order. For this package that happened to be the server; for 23 others it was the CLI. A third binary named after the package, on its own file, now always starts the server, and npx picks it by name.
